# Запуск на сервере через Docker

Стек состоит из Nuxt, Strapi и PostgreSQL. Сайт открывается без дополнительного
пароля по `http://SERVER_IP:3000`, админка — по `http://SERVER_IP:1337/admin`
со штатным входом Strapi. Публикации загружаются только из CMS; остальные
демонстрационные материалы используют локальные моки.

## Подготовка сервера

На Linux-сервере установите Docker Engine и Compose plugin по
[официальной инструкции для вашей ОС](https://docs.docker.com/engine/install/).
Проверьте `docker version` и `docker compose version`. Скопируйте репозиторий
на сервер и перейдите в его корневой каталог. Node.js и pnpm на сервере не нужны.

Откройте входящие TCP-порты 3000 и 1337 в настройках сети провайдера и сервера.
Порт 5432 открывать не нужно: PostgreSQL доступен только внутри Compose.

## Настройка и первый запуск

В следующей команде замените `203.0.113.10` на публичный IP сервера:

```bash
docker run --rm --user "$(id -u):$(id -g)" \
  -v "$PWD:/workspace" -w /workspace \
  node:22-bookworm-slim node scripts/setup-server.mjs 203.0.113.10

docker compose build cms
docker compose build web
docker compose up -d --no-build
docker compose ps
```

Генератор создаёт `.env` с публичным адресом Strapi и случайными секретами.
Файл не выводится в терминал, не попадает в Git и на Linux доступен только
владельцу. Сохраните его резервную копию в защищённом месте. Существующий `.env`
не перезаписывается. Если он уже есть, отредактируйте его вручную:
замените все значения `replace-with-...` и задайте публичные URL.
Compose проверяет наличие секретов, но не оценивает их случайность.

Для других портов добавьте к команде генератора
`--web-port 8080 --cms-port 8081` и откройте соответствующие порты.
Адреса и порты сохраняются в `.env`. `PUBLIC_URL` и
`NUXT_PUBLIC_STRAPI_URL` должны содержать внешний адрес CMS, а не `localhost`.
Серверный адрес CMS внутри Docker устанавливается автоматически.

После готовности сервисов откройте сайт и `/admin` по указанным адресам.
При первом запуске Strapi создайте администратора самостоятельно.
В Content Manager → Статьи создайте запись и нажмите Publish: только
опубликованные записи появляются на главной, в архиве и на страницах статей.
Публичные разрешения на чтение статей настраиваются при запуске Strapi.
Если опубликованных записей нет, сайт показывает пустой список;
недоступность CMS отображается как ошибка, без подстановки моковых статей.
HTTP не шифрует пароль и сессию администратора; для первоначальной настройки
можно использовать SSH-туннель либо сначала подключить HTTPS.

## Проверка индексации

```bash
curl -I http://203.0.113.10:3000/
curl -I http://203.0.113.10:3000/robots.txt
curl -I http://203.0.113.10:1337/admin
curl -I http://203.0.113.10:1337/robots.txt
```

В ответах должен присутствовать `X-Robots-Tag: noindex`. Этот заголовок
устанавливается обоими приложениями, включая их статические ресурсы, и по
умолчанию включён даже без переменных окружения. В `.env` оставьте
`WEB_INDEXING_ALLOWED=false` и `CMS_INDEXING_ALLOWED=false`.

В `robots.txt` намеренно нет `Disallow: /`: поисковик должен получить страницу
или файл, чтобы прочитать `noindex`. Доступ по ссылке остаётся публичным, боты
могут скачивать содержимое. Запрет действует на поисковики, соблюдающие
[директиву noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing).
Если страницы уже попали в поиск, удаление из выдачи требует повторного обхода.

## Если сборка Strapi завершается с heap out of memory

Сообщение `JavaScript heap out of memory` при `Building admin panel` означает,
что сборка исчерпала лимит памяти V8. Dockerfile задаёт для этого этапа
`--max-old-space-size=2048`; изменить значение в МиБ можно через
`CMS_BUILD_HEAP_MB` в `.env`. Этот параметр применяется только при сборке,
не меняет лимит работающей CMS и не добавляет физическую память серверу.

На сервере с 2 ГБ RAM без swap сборке может не хватить общей памяти даже
после увеличения лимита V8. Добавьте swap, увеличьте RAM или собирайте образы
на другой машине. Не собирайте CMS и web одновременно.

Для обычной Linux-файловой системы ext4 на сервере можно временно подключить
swap-файл размером 4 ГиБ. Сначала проверьте `df -h /` и `swapon --show`:
на диске должно быть больше 4 ГиБ свободного места. Следующие команды
выполняются от root и не перезаписывают существующий `/swap-desnica`:

```bash
test ! -e /swap-desnica && \
  (umask 077; set -C; : > /swap-desnica) && \
  dd if=/dev/zero of=/swap-desnica bs=1M count=4096 status=progress && \
  chmod 600 /swap-desnica && \
  mkswap /swap-desnica && \
  swapon /swap-desnica

free -h
docker compose build cms
docker compose build web
docker compose up -d --no-build
```

Swap, подключённый этой командой, не сохраняется после перезагрузки.
Для Btrfs и других файловых систем со специальными требованиями используйте
инструкцию своей ОС. В случае дальнейшего сбоя сохраните полный вывод
`docker compose --progress plain build cms`.

## Обновление и сохранность данных

После получения новой версии исходников:

```bash
docker compose build cms
docker compose build web
docker compose up -d --no-build
docker compose ps
docker compose logs --tail=100 web cms
```

База хранится в `postgres_data`, загрузки — в `cms_uploads`.
Пересборка и `docker compose down` сохраняют данные.
**`docker compose down -v` удаляет данные.** Делайте резервные копии базы,
загрузок и `.env` перед обновлениями. При существующей базе не генерируйте
заново пароль БД: смена значения в `.env` не меняет пароль внутри PostgreSQL.

## Домен и HTTPS позднее

Подключите домен к IP сервера и настройте reverse proxy с HTTPS.
Если proxy работает на хосте, привяжите порты приложений к `127.0.0.1` в
`compose.yaml`, чтобы входить только через proxy. Если proxy в Docker,
подключите его к сети сервисов и уберите внешнюю публикацию их портов.

Когда определитесь с адресом CMS, обновите `PUBLIC_URL` и
`NUXT_PUBLIC_STRAPI_URL`; при proxy установите `IS_PROXIED=true`.
После изменения адреса Strapi пересоберите сервис CMS, чтобы обновить админку.
Переход на домен сам по себе не разрешает индексацию.
Чтобы открыть сайт поиску, установите только `WEB_INDEXING_ALLOWED=true` и
выполните `docker compose up -d web`. Запрет для CMS останется включённым.
