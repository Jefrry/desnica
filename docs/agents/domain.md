# Доменная документация

Правила использования доменной документации инженерными навыками при изучении кодовой базы.

## Перед изучением кода

- Прочитать корневой `GLOSSARY.md`, если он существует.
- Прочитать относящиеся к рабочей области ADR из `docs/adr/`.
- Если эти файлы отсутствуют, продолжить работу без замечаний и без предложения создать их заранее. Навык `domain-modeling` создаёт их по мере появления подтверждённых терминов и решений.

## Структура файлов

Используется единый контекс:

/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── apps/

## Использование терминологии

В названиях задач, предложениях по рефакторингу, гипотезах и тестах использовать термины из `GLOSSARY.md`.

Если нужного понятия в глоссарии нет, проверить, не вводится ли ненужный новый термин. Реальный пробел следует отметить для последующей работы с навыком `domain-modeling`.

## Конфликты с ADR

Если предлагаемое изменение противоречит существующему ADR, явно указать это вместо молчаливой отмены решения.
