# WordPress: локальный запуск через Podman

Перед первым запуском установите зависимости репозитория командой
`pnpm install` из корня. `setup.ps1` использует их для сборки локальной подсветки кода.

В PowerShell из корня репозитория:

```powershell
cd apps/wordpress
./setup.ps1
podman compose up -d --build --wait
node ./localhost.mjs
```

Последнюю команду оставьте работать в отдельном окне: в проверенном Windows/WSL
автоматическое перенаправление портов не работает. Помощник подключает
`127.0.0.1:8080` к машине Podman; нужен имеющийся в проекте Node.js 22–26.
Если Podman уже сам открывает localhost:8080, помощник не нужен.

Сайт: <http://localhost:8080/>. Админка: <http://localhost:8080/wp-admin/>.
При первом открытии завершите обычную установку WordPress: название
«Ресурсный центр», свои логин, пароль и email. Тема активируется автоматически.
Установка не переносит данные Strapi; проверочные данные не создаются при запуске.
В текущем проверенном окружении установка уже выполнена; данные администратора
сохранены только локально в `.tmp/wordpress-admin.json` в корне репозитория.

PHP/CSS темы в `theme/` и локальный запрет индексации в `mu-plugins/` подключены
с компьютера: сохраните файл и обновите страницу. Пересборка не нужна.

Для работы с публикациями `setup.ps1` скачивает бесплатный Markup Markdown
4.0.2 из каталога WordPress. На существующей установке повторите `./setup.ps1`
и `podman compose up -d --force-recreate --wait`, чтобы подключить плагины.
В админке активируйте сначала **Markup Markdown**, затем **Публикации
Ресурсного центра**. Назначайте авторам штатную роль **Автор**.
Исходники плагина сайта в `plugins/resource-center-publications/`
подключены с компьютера и обновляются без пересборки.

Статья и оглавление рендерятся в PHP. Для рендера нужны расширения DOM и
mbstring. Подсветка кода подключается отдельным локальным скриптом.
## Комплект для FTP

В PowerShell 7 из корня репозитория после `pnpm install`:

```powershell
./apps/wordpress/package-ftp.ps1
```

Готовый архив появляется в `apps/wordpress/dist/resource-center-ftp.zip`.
Сборка использует редактор из кеша `setup.ps1` либо скачивает его из каталога
WordPress. Если сборочная машина без интернета, передайте официальный
[`markup-markdown.4.0.2.zip`](https://downloads.wordpress.org/plugin/markup-markdown.4.0.2.zip)
параметром `-MarkupMarkdownZip`. На хостинге сборка не нужна.
Инструкция [FTP.md](FTP.md) также входит в архив.

## Повторный локальный запуск

Остальные команды — в другом PowerShell из `apps/wordpress`:

```powershell
podman compose up -d --build --force-recreate --wait # после правок Dockerfile/php-local.ini/apache-local.conf/compose.yaml
podman compose stop                             # остановка
podman compose up -d --wait                      # повторный запуск
```

Перенаправление остановите Ctrl+C в его окне; при необходимости снова запустите
`node ./localhost.mjs`. После перезапуска машины Podman перезапустите помощник,
чтобы он заново определил её адрес.

Данные живут в отдельных томах `desnica-wordpress_mysql_data` и
`desnica-wordpress_wordpress_data`. `stop`, `up` и пересборка их сохраняют.
Не используйте `down -v` и не удаляйте тома. `.env` содержит сгенерированные
локальные пароли БД, исключён из Git; повторный `setup.ps1` его не меняет.
Не меняйте пароли в `.env` после создания MySQL без отдельной смены паролей в БД.

Точные образы закреплены по digest: WordPress 6.7.1, PHP 8.3.16,
Apache 2.4.62, MySQL Community 8.0.40, Linux amd64. Ядро, плагины и темы
не обновляются через админку локального окружения. Эти версии не являются
подтверждением конфигурации Timeweb. Индексация заблокирована локальным
обязательным плагином: HTTP-заголовок, meta robots, robots.txt.
