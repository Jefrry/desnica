# 03: Собрать архив публикаций с заменяемым источником

**What to build:** Создать полноценный архив «Новости», который работает с единым источником публикаций, поддерживает настоящую пагинацию и все состояния коллекции, а позднее переключается с моков на существующую CMS без переделки страницы.

**Blocked by:** 01: Укрепить базовые контракты и режим предпросмотра.

**Status:** ready-for-agent

- [ ] Определён единый типизированный контракт источника публикаций для списка, отдельной публикации и pagination metadata.
- [ ] Preview-источник возвращает двенадцать согласованных публикаций с размером страницы шесть и двумя страницами.
- [ ] CMS-адаптер сохраняет существующий API и возвращает вызывающему коду реальные page, pageSize, pageCount и total.
- [ ] Ошибка CMS не заменяется демонстрационными публикациями.
- [ ] Архив показывает шесть карточек на странице: три колонки на desktop, две на tablet и согласованный mobile-список.
- [ ] Первая страница использует базовый адрес архива, последующие — query `page=N`; отдельный маршрут вида `page/N` не создаётся.
- [ ] Текущая страница имеет `aria-current`, многоточие не является ссылкой, а предыдущая и следующая ссылки корректно отключаются на границах.
- [ ] При единственной странице номера пагинации не выводятся.
- [ ] Нечисловое или отрицательное значение нормализуется к первой странице с исправлением URL.
- [ ] Числовая страница за пределами архива показывает честное состояние отсутствия.
- [ ] Реализованы pending, empty, error, retry и success без вывода внутренних сообщений сервиса.
- [ ] После явной смены страницы объявляется её номер и фокус переходит к заголовку списка.
- [ ] Переход в публикацию сохраняет известную страницу архива и позволяет вернуться к ней и приблизительной позиции списка.
- [ ] Title и canonical отражают выбранную действительную страницу архива.
- [ ] Lint, проверка типов и production-сборка проходят.
