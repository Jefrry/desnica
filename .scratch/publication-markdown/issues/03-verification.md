# 03: Проверить отображение публикаций

Подтвердить [критерии приёмки](../spec.md) после реализации задач 01–02. Выполнять после отдельного поручения на реализацию.

## Работа

- Добавить регрессионную проверку реального пути обработки содержимого: исходная строка CMS → очищенное форматирование и оглавление. Убедиться, что проверка обнаруживает первоначальный дефект со звёздочками.
- Сравнить один набор примеров с предпросмотром установленной Strapi: основной Markdown, расширения, HTML и оговорённые исключения.
- Проверить потенциально опасные HTML и URL, относительные изображения, повторяющиеся заголовки и обычный текст.
- Проверить статью в браузере на широком экране и при ширине 320–390 CSS px, первоначальную загрузку и внутреннюю навигацию, прямой hash, переходы из оглавления и историю браузера.
- Выполнить lint, проверку типов и сборку проекта. Записать результаты и фактические ограничения в ответ задачи.

### Приёмка в браузере

- Фактически работающие адреса: web `http://172.24.0.1:3000`, CMS
  `http://172.24.0.1:1337`. Переданный адрес web на 1337 открывает Strapi;
  `172.27.180.179:1337` при прямой проверке отвергал соединение. Конфигурация
  окружения проекта не изменялась; публичный URL изображений берётся из неё
  (`http://192.168.0.10:1337`).
- Создана и оставлена опубликованная статья «Проверка Markdown — пункт 03»:
  `/news/markdown-verification-03`, documentId `efwjycids2pd27o195ovuwky`.
  Тот же набор примеров просмотрен в штатном предпросмотре редактора Strapi и
  на сайте. Для реальных изображений вместо условного пути из файла-примера
  использован загруженный в CMS JPG логотипа из репозитория
  `/uploads/resource_center_logo_color_4dc436c04a.jpg` (1885 × 791).
- Подтверждены жирный текст без звёздочек, курсив, зачёркивание, ссылки,
  переносы (включая буквальный `\\n`), вложенные списки, цитата, разделитель,
  таблицы, код, все перечисленные расширения и очищенный HTML. В предпросмотре
  видеоплееры присутствуют; публичная статья их исключает согласно спецификации.
  Название и анонс остаются обычным текстом.
- В статье один H1. Три пункта оглавления соответствуют трём реальным H2,
  повторяющиеся заголовки имеют разные стабильные ID. Проверены прямой URL с
  hash, обновление, переход из архива без полной загрузки, клики оглавления,
  back/forward между двумя якорями. Фокус следует соответствующему H2; заголовок
  виден ниже фиксированной шапки.
- Проверены 1440, 390 и 320 CSS px. На узких экранах scrollWidth страницы
  соответственно 375 и 305 при innerWidth 390 и 320 (с полосой прокрутки);
  горизонтальной прокрутки страницы нет. Оба относительных изображения реально
  загружаются, naturalWidth 1885, ширина при 320 px — 273 px. Таблица ограничена
  колонкой статьи, длинная строка кода прокручивается внутри блока
  (scrollWidth 1315 при clientWidth 271 на 320 px).
- Исходный серверный HTML статьи возвращает 200 и уже содержит `<strong>слово</strong>`
  и уникальный ID повторного заголовка до выполнения браузерного JavaScript.
- Создан и оставлен **неопубликованный** черновик «Проверка Markdown — только
  черновик 03», slug `markdown-verification-draft-03`, documentId
  `p3mcr717mvm6de8e5z1n61lx`. Публичный API списка его не возвращает; API по slug

  публикации; кнопка возврата открывает архив.
