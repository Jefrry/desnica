# Форматирование содержимого публикаций

## Состояние согласования

План согласован 20 октября 2026 года: пользователь принял все рекомендации из обсуждения. Текущий этап — исследование и планирование. Начало реализации требует отдельного поручения пользователя.

## Проблема

Поле `content` публикации в Strapi содержит Markdown. Фронтенд преобразует его в обычные абзацы через `adaptPlainTextArticleContent`, затем `ArticleBody` выводит строки текстовой интерполяцией. Например, `**слово**` показывается со звёздочками вместо жирного начертания.

Такое поведение соответствовало прежней задаче [04-publication-detail](../resource-center-remaining/issues/04-publication-detail.md). Эта спецификация заменяет её ограничение на вывод содержимого CMS только обычным текстом. Требования к единому источнику публикаций из [ADR 0001](../../docs/adr/0001-content-sources-and-preview-mode.md) сохраняются.

## Согласованные решения

- Полный текст статьи интерпретируется так же, как в штатном предпросмотре Markdown-редактора установленной Strapi. Шрифты, цвета и отступы соответствуют дизайну публичного сайта.
- Поддерживается весь штатный набор Markdown предпросмотра, включая его расширения. HTML автора допускается после очистки по совместимой с предпросмотром политике. Скрипты, обработчики событий и опасные URL удаляются.
- Видеовставки, iframe и плееры остаются вне задачи согласно прежнему решению владельца.
- Единственный H1 — название публикации. Если в содержимом есть H1, уровни заголовков всего содержимого сдвигаются на один: H1 → H2, H2 → H3 и далее до H6; H6 остаётся предельным уровнем. Если H1 отсутствует, уровни H2–H6 сохраняются. Правило действует и на разрешённые HTML-заголовки.
- Оглавление сохраняет существующий формат: разделы H2 после нормализации. Его пункты и идентификаторы формируются из того же результата разбора, что и тело статьи.
- Исходный Markdown, схема CMS и API сохраняются; миграция публикаций не требуется.
- Название, анонс `excerpt` и SEO-описание остаются обычным текстом. Форматирование применяется к полному содержимому публикации.

## Ориентир совместимости

Исследован код предпросмотра установленного `@strapi/content-manager` версии 5.55.1: `Wysiwyg/utils/mdRenderer.mjs`, `PreviewWysiwyg.mjs`, `utils/sanitizer.mjs`.

Предпросмотр использует `markdown-it` с обработкой HTML, переносов строк, автоматических ссылок и типографики; расширения сокращений, контейнеров warning/tip, списков определений, эмодзи, сносок, вставок, выделения, нижних и верхних индексов; подсветку кода. После преобразования HTML очищается. При реализации сверяться с установленным пакетом, включая обработку буквальных `\n` и поведение сносок.

Совпадение с предпросмотром ограничено согласованными исключениями: оформление сайта, нормализация заголовков и отсутствие видеовставок. Изменения поведения для этих исключений проверять явно.

## Критерии приёмки

- `**слово**` отображается жирным, а Markdown-маркеры не видны как обычный текст там, где предпросмотр воспринимает их как разметку.
- Проверены курсив, зачёркивание, ссылки, переносы, вложенные списки, цитаты, разделители, таблицы, встроенный и блочный код, изображения и перечисленные расширения Strapi.
- Разрешённый HTML сохраняет форматирование; исполняемое содержимое и опасные URL не попадают в результат. Очистка работает одинаково при серверном рендеринге и в браузере.
- На странице ровно один H1; оглавление содержит только существующие H2 с уникальными стабильными идентификаторами. Прямые ссылки, клики и история браузера работают с сохранением управления фокусом.
- Изображения из `/uploads/...` разрешаются относительно CMS; ссылки на разделы статьи остаются локальными. Изображения и широкие таблицы не ломают мобильную вёрстку.
- Сохраняются чтение обычного текста, загрузка по slug, состояния 404 и ошибки CMS, опубликованность и возврат в архив.
- Проверены первоначальная серверная загрузка и переход к статье внутри сайта. Пройдены lint, проверка типов и сборка.
