# Перенос «Ресурсного центра» на PHP 8 и WordPress 6.7.1

## Problem Statement

Владелец сайта хочет размещать «Ресурсный центр» на виртуальном хостинге Timeweb, загружая подготовленные файлы по FTP. Текущий проект на Nuxt, Strapi и PostgreSQL рассчитан на другое серверное окружение и не соответствует этому способу установки. На хостинге уже развёрнут, по описанию владельца, чистый базовый WordPress 6.7.1 с настроенной базой.

Необходимо перенести весь действующий сайт на PHP 8 и строго WordPress 6.7.1, сохранив внешний вид и бизнес-поведение с согласованными изменениями редакторской роли. Разработка должна идти рядом со старой версией без удаления её файлов. Главный приоритет — страницы, которые видят посетители. Владелец хочет проверять изменения локально с чистой MySQL в контейнерах через Podman и получать очень короткие инструкции запуска и обновления.

## Solution

Создать классическую PHP-тему WordPress для публичного сайта и отдельный плагин для правил публикаций и интеграции сайта. Использовать готовое ядро WordPress 6.7.1 и бесплатный редактор Markup Markdown после проверки совместимости. Через админку на первом этапе редактируются только публикации; остальные разделы сохраняют встроенное содержание. Применяется стандартная роль WordPress «Автор».

Локально весь новый стек — WordPress, PHP, веб-сервер и MySQL — запускается в контейнерах через Podman. Упоминания Docker в раннем обсуждении означают контейнерный подход, а не требование Docker Desktop или Docker Engine. На Timeweb устанавливаются готовые файлы темы, плагина сайта и Markdown-редактора в уже существующий WordPress; используется его подключение к базе. Загрузка файлов дополняется короткой инструкцией активации и настройки. База с компьютера не заменяет базу хостинга.

## Implementation Decisions

- Целевой стек — PHP 8, строго WordPress 6.7.1 и MySQL. Конкретные версии PHP 8.x и MySQL фиксируются после сверки доступности на Timeweb; предварительный ориентир — PHP 8.3 и MySQL 8.0. Конфигурация конкретного аккаунта пока не проверена. Локальная версия ядра закрепляется; влияние автоматического обновления ядра на хостинге проверяется отдельно.
- Новая реализация изолирована в отдельном каталоге рядом с текущими приложениями и имеет собственное контейнерное окружение для Podman. Формат Compose допускается, но выбранный способ его запуска и зависимости проверяются именно с Podman. Docker Desktop и Docker Engine не являются обязательными предпосылками. Старые приложения, их конфигурация и том PostgreSQL сохраняются. Код старого стека используется как эталон, а не как обязательный сервис новой версии.
- Порядок реализации: минимальная локальная среда, необходимая для просмотра PHP-страниц; публичная часть; подключение публикаций и редактора; комплект установки на Timeweb; итоговая приёмка. Полный перенос редакционной части не должен отодвигать работу над публичными страницами.
- Классическая PHP-тема отвечает за отображение, структуру страниц и ресурсы интерфейса. Отдельный плагин сайта отвечает за правила публикаций, нужные поля, маршруты и согласованную интеграцию Markdown. WordPress предоставляет базу, записи, пользователей, медиатеку и админку.
- Публичная часть сохраняет дизайн, тексты, адаптивность и интерактивное поведение текущей версии. Допускаются CSS и небольшой браузерный JavaScript. Постоянно работающий Node.js на целевом хостинге не нужен; необходимые подготовленные зависимости входят в комплект поставки.
- Сохраняются главная, раздел организации с миссией, документами и отчётами, каталог четырёх услуг и их страницы, обучение, «Новости», статья, работа НКО, контакты и правовая страница. Программы обучения не получают новых отдельных страниц.
- Сохраняются публичные URL и значимые параметры ссылок: выбор документа и года отчёта, разделы материалов, страница архива, контекст возврата к карточке публикации и правовой якорь. Прямое открытие и обновление страницы должны работать без предварительного перехода с главной.
- Текстовая версия документа доступна независимо от файла документа. Наличие файла проверяется отдельно; отсутствующие фотографии, документы, контакты и правовые тексты не заменяются выдуманными подтверждёнными материалами. Поведение демонстрационных материалов переносится по текущему коду и поздним решениям проекта.
- Через админку на первом этапе меняются только публикации. Остальные разделы и навигация остаются встроенными. Используются штатные записи WordPress; скрытые демозаписи не создаются для заполнения пустого архива.
- Публикация сохраняет обязательные заголовок до 200 символов, уникальный slug, календарную дату и содержимое Markdown; необязательные анонс до 500 символов и одну обложку с альтернативным описанием. Календарная дата не подменяется временем перехода в опубликованное состояние; для новой публикации по умолчанию используется текущая дата.
- Генерация slug сохраняет текущую транслитерацию русского текста и разрешение коллизий числовыми суффиксами. Изменение заголовка само по себе не меняет URL. Поскольку импорт из Strapi исключён, новые записи используют идентификаторы WordPress без таблицы соответствий со старой CMS.
- Публичные выборки показывают только опубликованные записи. Архив содержит шесть записей на странице и сортируется по календарной дате по убыванию, затем стабильно по ID WordPress по возрастанию. Некорректные номера страниц обрабатываются согласно текущему пользовательскому поведению.
- Пустой архив, неизвестная публикация и техническая ошибка остаются различимыми состояниями. Неизвестный slug даёт 404. Ошибка источника не превращается в пустой архив, фиктивную статью или 404 и не раскрывает внутренние сообщения. Старый отдельный API Strapi и обусловленная им 502 не являются обязательной архитектурой нового монолитного сайта; статус серверной ошибки должен соответствовать реальному сбою.
- Применяется стандартная роль WordPress «Автор» без расширения прав до редактирования чужих публикаций. Автор работает со своими записями, включая удаление, и может загружать файлы. Это явное согласованное отличие от прежней роли Strapi, имевшей права на статьи всех авторов.
- Для Markdown выбран готовый бесплатный Markup Markdown, а не собственный редактор с нуля. Перед закреплением версии проверяются его требования, запуск с WordPress 6.7.1/PHP 8 и работа под стандартной ролью автора. При несовместимости допускается подобрать бесплатную совместимую замену; существенные изменения редакционного поведения нельзя принимать молча.
- Бесплатность относится к написанию, редактированию и публикации Markdown без обязательной лицензии или подписки. Добровольные пожертвования, платные доработки и профессиональная поддержка автора не включаются в обязательные расходы проекта.
- Документированное отсутствие совместимости редактора Markup Markdown со скринридерами принято: пользователь подтвердил, что авторы ими не пользуются. Это не отменяет требований к доступности публичного сайта.
- Сохраняется действующий расширенный Markdown: базовое форматирование, переносы строк, ссылки, изображения, таблицы, зачёркивание, сокращения, списки определений, emoji, сноски, вставки и выделения, нижние и верхние индексы, блоки warning/tip и подсветка кода. Готовый плагин не считается автоматически совместимым со всем набором: недостающие возможности обеспечиваются интеграцией сайта либо оформляются как явно согласованные отклонения.
- Содержимое проходит очистку опасного HTML, обработчиков событий и опасных URL. Встраиваемые iframe, видео и аудио не добавляются. Заголовок страницы остаётся единственным H1; H1 внутри публикации вызывает согласованный сдвиг уровней до H6. Оглавление строится по итоговым H2 с устойчивыми уникальными якорями, в том числе при повторяющихся заголовках.
- Отображение статьи и оглавление используют один результат обработки содержимого. Повторный прогон уже сформированного HTML через Markdown и расхождение тела статьи с оглавлением недопустимы.
- Локальная MySQL создаётся чистой и хранит данные в постоянном томе. Исходники темы и плагина подключаются с компьютера, чтобы обычные изменения PHP/CSS/JavaScript были видны без пересборки. Пересборка необходима при изменении образов или зависимостей, а не после каждого изменения страницы.
- Краткая инструкция должна содержать проверенные для Podman действия первого запуска, применения обычных изменений, пересборки окружения, остановки и повторного запуска, адреса сайта и админки. Проверяются подключения исходников, сеть сервисов и постоянные тома в фактическом окружении Podman на Windows. Обычное обновление не должно удалять том базы.
- Комплект для FTP содержит тему, плагин сайта, бесплатный Markdown-плагин и нужные готовые зависимости. На Timeweb для работы сайта не требуются Docker, Composer или Node.js. После загрузки необходимы активация и минимальная настройка средствами WordPress.
- Существующая конфигурация соединения с базой и пользователи WordPress на хостинге сохраняются. Локальная база не импортируется поверх хостинговой; базовые записи установки не удаляются автоматически. Перед изменением хостинговой установки предусматривается резервная копия и возможность возврата.
- Выбор WordPress для новой версии заменяет выбор Strapi как источника публикаций из прежнего архитектурного решения «Источники содержимого» и зафиксирован в ADR «PHP и WordPress для развёртывания на Timeweb». Правила опубликованности и отсутствия подстановок при ошибке сохраняются. Поздние решения и действующий код имеют приоритет над устаревшими описаниями удалённых функций.

## Testing Decisions

- Основной уровень проверки — работающий WordPress через публичные HTTP-страницы и браузерный сценарий «автор создаёт запись → сохраняет черновик → публикует → посетитель читает». Это проверяет тему, плагин правил сайта, готовый Markdown-редактор и реальную MySQL совместно. Не подменять реальные компоненты, взаимодействие которых необходимо подтвердить.
- Проверять внешнее поведение: доступное содержимое, переходы, права, ответы HTTP, результат отображения Markdown и сохранность данных. Не проверять приватные методы, внутреннюю структуру модулей, названия PHP-файлов или точное устройство SQL-запросов.
- Для случаев Markdown, которые трудно полно проверить одним браузерным сценарием, использовать один узкий контракт «исходный Markdown → очищенное тело статьи и оглавление». Опорой служат существующие проверки Markdown, детальной страницы, совпадения с прежним предпросмотром и общий набор примеров; их пользовательские ожидания переносятся без зависимости новой реализации от Strapi.
- Набор Markdown включает вложенное форматирование, переносы, таблицы, специальные блоки и выделения, сноски, изображения, код, повторяющиеся и пустые заголовки, HTML-заголовки, опасный HTML и URL. Проверяется согласованность якорей и оглавления. Побайтовая идентичность HTML разных библиотек не обязательна, если семантика и пользовательское поведение совпадают.
- Проверить сквозные сценарии создания, повторного открытия, предпросмотра и публикации статьи под ролью «Автор», загрузки изображения, задания даты и анонса, сохранения slug при изменении заголовка. Проверить отсутствие доступа к чужим статьям и управлению системой, а также стандартное удаление собственных записей.
- Для архива использовать отдельные проверочные записи с несколькими датами и достаточным количеством для двух страниц. Проверить сортировку, размер страницы, пустую базу, отсутствие черновиков у анонимного посетителя, неизвестный slug, некорректный номер страницы и возврат из статьи к исходной карточке. Данные сценария не должны скрыто заполнять чистую базу обычного запуска.
- Сопоставить все публичные страницы со старой версией на настольных и мобильных размерах, включая ширины 1440, 390 и 320 пикселей. Проверить меню, Escape, возврат фокуса, FAQ, выбор документа и года, прямые ссылки, back/forward, правовой якорь и ошибку 404. Проверить увеличение до 200% и клавиатурную навигацию. Непроведённую проверку скринридером нельзя обозначать выполненной.

Проверить обоснованную пересборку окружения без потери базы. Проверка только через Docker не является подтверждением работы через Podman. Старый стек и его данные должны остаться доступны в прежнем виде.

Убедиться, что загрузка/активация не меняет соединение с базой, не уничтожает записи и не оставляет локальные URL. Проверить прямые маршруты, изображения, запрет индексации по умолчанию и отсутствие ошибок PHP/JavaScript.
- Фактическую проверку на Timeweb выполнять при доступности установки. Локальная имитация не является подтверждением успешной установки на реальном хостинге. В результате отдельно указывать выполненные проверки, недоступные проверки и ограничения. Существующие тесты старого приложения не являются тестами PHP-версии.

## Out of Scope

- Редизайн, изменение бренда «Ресурсный центр», новые услуги, программы или публичные функции.
- Удаление старой реализации, её зависимостей, конфигурации или данных; перенос публикаций, пользователей, черновиков и медиа из Strapi.
- Редактирование через WordPress всех информационных страниц, навигации, услуг, документов и отчётов на первом этапе.
- Возвращение ранее удалённых формы обращения, отправки сообщений, карты, блока входа, контекста обращения и видеовставок. Термины исторического глоссария об обращениях не служат основанием восстановить эти функции.
- Расширение стандартной роли «Автор» правами работы с чужими статьями или управления системой.
- Обязательные платные плагины, подписки и покупка профессиональной поддержки для работы Markdown.
- Обязательная доступность редактора админки для скринридеров при текущем составе авторов. Доступность публичного сайта остаётся в объёме работ.
- Обновление WordPress до другой версии вместо строго указанной 6.7.1 без изменения требования владельцем.
- Развёртывание Docker или отдельного Node.js-сервера на Timeweb; полная переустановка хостинговой CMS или замена её базы локальной.
- Подготовка отсутствующих реальных документов, фотографий, контактов и юридических текстов; открытие индексации без отдельного решения.
- Фактическая реализация приложения, установка системного ПО или публикация сайта в рамках текущей задачи синтеза спецификации.

## Further Notes

- Спецификация синтезирует ответы пользователя и изученный код. По последней команде to-spec интервью не продолжается; отдельное дополнительное согласование уровней тестирования не запрашивалось. Предложенные проверки опираются на обсуждённое сохранение поведения и существующие тестовые контракты.
- Материал опубликован в локальном Markdown-трекере с меткой ready-for-agent. Это готовность спецификации к реализации, а не утверждение о выполненном переносе, установленном ПО или предоставленном доступе к хостингу.
- Первичная проверка Windows не обнаружила доступных команд PHP, Composer, Docker и клиента MySQL; в проверенных стандартных папках PHP и Docker также не найдены. Команда WSL доступна, но работоспособность Linux-окружения не подтверждена. Это не исключает нестандартных установок. Пользователь позднее уточнил, что локальные контейнеры будет запускать через Podman; наличие и работоспособность Podman пока не проверены, отсутствие Docker не является препятствием для выбранного подхода. При полном контейнерном запуске отдельно устанавливать PHP и Composer в Windows для работы сайта не требуется.
- На хостинге, со слов пользователя, чистый WordPress; фактические версии PHP/MySQL, плагины, содержимое базы и настройки панели пока не исследованы. Эти факты выясняются технической проверкой. Неизвестные параметры нельзя объявлять подтверждёнными.
- Бесплатность Markup Markdown проверена по [каталогу WordPress](https://wordpress.org/plugins/markup-markdown/) и [странице поддержки автора](https://www.markup-markdown.com/support/): бесплатная загрузка и использование редактора, профессиональные услуги предлагаются отдельно. Совместимость с целевым стеком и полный набор Markdown ещё не проверены запуском.
- Сведения Timeweb о версиях и смене PHP опубликованы в [технических параметрах хостинга](https://timeweb.com/ru/docs/virtualnyj-hosting/obshchaya-informaciya-o-hostinge/osobennosti-tekhnicheskogo-resheniya/) и [инструкции настройки PHP](https://timeweb.com/ru/docs/virtualnyj-hosting/php/izmenenie-versii-php/). Это сведения о платформе, а не доказательство настроек аккаунта пользователя.
- Разделение на отдельные задачи реализации выполняется следующим шагом; настоящая спецификация не подменяет набор отдельных задач одним объединённым файлом.
