# 10: Первая публикация через Markdown-редактор

**What to build:** Стандартный автор WordPress создаёт статью в бесплатном Markdown-редакторе, сохраняет черновик, проверяет предпросмотр и публикует её для посетителя на PHP-странице.

**Blocked by:** 02.

Все требования спецификации миграции и ограничения по сохранности старого проекта действуют для этой задачи. Проверки включаются в результат задачи; отдельная задача приёмки не заменяет их.

## Acceptance criteria

- [ ] Выбрана и закреплена версия бесплатного Markup Markdown, фактически проверенная на WordPress 6.7.1/PHP 8. Написание и публикация не требуют оплаты или подписки. При несовместимости подобрана бесплатная замена; существенные отклонения оформлены явно.
- [ ] Используются штатные записи WordPress и стандартная роль author без расширения прав на чужие статьи и управление системой. Проверены создание, редактирование, публикация и удаление собственной записи, загрузка файла и запреты на чужие записи.
- [ ] Публикация содержит заголовок до 200 символов, уникальный slug, обязательные календарную дату и Markdown, необязательные анонс до 500 символов и одну обложку с alt.
- [ ] Для новой записи календарная дата по умолчанию — текущий день; её можно задать отдельно от системного времени публикации.
- [ ] Slug транслитерируется по текущим правилам, коллизии разрешаются числовыми суффиксами; изменение заголовка не меняет постоянный URL.
- [ ] Создание, сохранение, повторное открытие, предпросмотр и публикация проверены через настоящие WordPress и MySQL. Статья отображается в общей теме с датой, анонсом, обложкой и базовым Markdown.
- [ ] Анонимный посетитель не получает черновик по прямой ссылке; неизвестный slug возвращает 404. Опубликованная статья открывается напрямую и после обновления.
- [ ] Опасный HTML и URL очищаются уже в базовом сценарии; выполнение скриптов и появление iframe, видео или аудио не допускаются.
- [ ] Обычный запуск по-прежнему не импортирует Strapi и не заполняет чистую базу проверочными записями. Ограничение скринридеров редактора принято; доступность публичной страницы сохраняется.

## Comments

- Состав и зависимости согласованы пользователем. Публичные информационные страницы имеют приоритет перед редакционной частью; порядок номеров задаёт приоритет, а блокирующие связи — технические зависимости.
